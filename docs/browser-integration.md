# Integrated browser

The Browser surface keeps MonoCode’s existing toolbar, home shortcuts and right-panel formats. Enter an HTTP/HTTPS URL, a domain, localhost address or Google search. Explicit non-web URLs and recognized non-web schemes are rejected; native navigation only accepts HTTP/HTTPS. Command failures appear in the surface rather than silently succeeding. Annotation is not implemented and is not advertised as working.

## Browse and search

Open the right panel, then press **B** outside an editor, text field or owned overlay. This activates an existing Browser tab or creates one. Enter a domain such as `google.com`, a complete HTTP/HTTPS URL, or search text such as `Tauri WebView2 embedded browser`, then press **Enter**. Search text opens Google results inside the native Browser, not an external browser. Unicode and spaces are encoded in the search query. Ordinary colon-containing queries, including `TypeError:Cannot read properties of undefined`, `TypeError:Cannot` and `Error:404`, are also searched; a colon alone does not make query text a navigation protocol. Google operators such as `site:github.com`, `intitle:browser`, `filetype:pdf` and `after:2025-01-01` remain search text rather than being rejected as URL protocols; non-web protocols such as `javascript:` and `file:` are still rejected.

Use Back, Forward and Reload in the toolbar. Additional Browser tabs keep their own native pages. This is an embedded WebView2 browser on Windows, not a complete replacement for a standalone browser: popup windows are denied, cookies/storage may be shared, and sites can impose login, CAPTCHA, DRM or embedded-browser restrictions. Successful page navigation does not guarantee every site's features.

## Native ownership and history

Each browser/device tab owns a lazy native child Webview in its workspace window. Navigation creates it hidden; only active, non-occluded geometry shows it. Resize/scroll never navigate. Bounds use logical window coordinates, adjusted for app zoom. Native page-load/title events capture immutable window and tab IDs at creation; React rejects events from other tabs, including late events after switching. Every operation carries that tab identity. Legacy command names remain supported; omitting tab identity targets the legacy view, except hide/close which cover all browser children in the caller's window. The remote page has no remote IPC capability or injected privileged bridge. Rust also rejects browser-child Webview caller labels before resolving their containing window (defense-in-depth alongside ACL origin protection). Popup windows are denied.

Back/Forward invoke the selected tab's scoped native history command exactly once; reducer history changes never load a fresh document. On Windows, Tauri's existing WebView2 controller supplies CanGoBack/CanGoForward on load, title and restore observations, and the toolbar uses those native values when supplied. Other platforms fall back to reconciled URL history. Traversal intent and navigation observations without a fresh native query invalidate older availability flags, so fragment-only traversal cannot reuse a previous document's disabled Forward state.

Observations distinguish navigation, load, title and restore phases. Redirect/intermediate URLs remain provisional until completion; a final redirected URL replaces an explicit request's provisional entry instead of adding another document. Back/Forward record traversal intent and reconcile the completed destination within known history while preserving the opposite direction. Late departure loads and titles cannot branch history; titles alone never move its cursor. Fragment-only same-document observations reconcile without requiring page-load callbacks.

The snapshot fallback is not a native entry-ID/index API: repeated identical-URL documents, arbitrary SPA History API changes without native callbacks, and multiple unseen visits while the panel is closed cannot be reconstructed exactly. Native availability helps on Windows but does not make those snapshots a complete session/history implementation. Document/form-state preservation depends on native history; runtime smoke must establish it. Native page titles may arrive after load completion.

Switching hides the old native child and shows the selected tab without navigating it to stale React state. Initial/remount navigation uses the legacy navigate command's optional `restore` mode: an existing child reports its current URL rather than loading another document. Removed tabs close their children, including in-flight lazy creation. Cookies/storage may still be shared; separate Webview identity is not isolated-session support.

Device view is a rectangular available-area viewport preview, not mobile user-agent/touch emulation or a scaled native page. Its native bounds intersect the browser rectangle, scrolling device canvas and window viewport. When partially scrolled off-canvas, the native viewport shrinks and reflows inside the remaining visible rectangle; it does not crop a larger, preserved mobile viewport. DOM transforms size the frame, not native text or input. Rounded native clipping is not provided. The rectangular page cannot escape the canvas over app chrome. Preset/scale changes explicitly invalidate geometry; CSS transforms need not trigger ResizeObserver.

## Container integration

RightPanelContainer subscribes once for all Browser/Device tabs and dispatches `native_observation` by exact tab identity, including hidden tabs. The adapter's single native listener/cache lives with the shell Webview, not an active surface or open panel; reopening replays current cached URL/title/loading observations. Surface subscriptions and panel subscriptions detach on unmount, while that window-lifetime native listener continues caching events. Closed-tab cache entries are removed with native close.

`BrowserSurface` accepts optional `onNativeNavigate(tabId, url, loading, title?)` for observation-only updates. In the integrated panel the persistent owner handles those updates; do not issue native navigation from that callback. Explicit address/home navigation increments `navigationToken`; native observations and Back/Forward do not. Observation `kind` prevents late title notifications or redirect intermediates from masquerading as new user visits. Geometry never accepts a navigation request: supplying the retained legacy `url` argument is rejected with `Browser bounds do not support url; use browser_navigate` before native geometry changes; the TypeScript adapter rejects it without IPC.

RightPanelContainer observes the existing dialog, popover and model-picker markers, excluding hidden/inactive owners, and forwards `blocked` to both BrowserSurface and DeviceSurface. Relevant DOM mutations and native popover toggle events update blocking; unrelated terminal/text mutations do not trigger visibility scans. Native child Webviews render above DOM overlays, so DOM z-index alone cannot occlude them. Occlusion changes hide/restore immediately; resize/scroll work is animation-frame coalesced. DeviceSurface also supplies the canvas clipping reference.

Hiding/unmounting does not suspend page CPU. Inactive tabs remain hidden; removal closes their native children and owner-window destruction handles remaining children. Component observers/subscriptions and scheduled frames are removed on cleanup. A component subscription resolving after teardown is immediately detached and cannot create a removed tab; the window-lifetime cache listener intentionally remains. A newly selected tab's navigation is still issued after its own listener is registered.

## Verification boundary

Focused mocked tests, TypeScript and Rust checking do not prove native rendering. Native smoke must use a rebuilt executable and an isolated workspace, verifying initial navigation, links/redirects, loading/title updates, panel resize, app zoom, overlays, tab/window switching and cleanup. Do not use an already-running older user process as evidence or terminate it. Recovered native smoke evidence reports Back/Forward and Google loading passed; the prior captures were visually read. That evidence is historical and does not establish freshness for the current executable. The optional Google smoke now types a free-text query through the shipped toolbar and requires a successful native search response, visible result links and a synchronized shell URL; CAPTCHA/network errors are failures, not successful search proof. The current isolated release build succeeded. Its native smoke passed 14 checks (including Back/Forward, model overlays, Device and Google loading) but ended partial: the toolbar search `site:tauri.app WebView2` reached Google's `/sorry/` reCAPTCHA instead of verifiable results. The challenge was captured inside the native panel. Human intervention is required; do not claim successful result-search proof or automatically bypass the challenge. The final closed-panel B probe did not run in that smoke. After the user completed the CAPTCHA manually, a bounded continuation passed: ten actual result links for the requested query, matching toolbar URL, closed-panel B behavior and restoration without navigation. `search-after-captcha.json` records that passed continuation separately; the original partial evidence remains unchanged. The native search-results screenshot was visually read and confirms real results inside the right panel. This proves the tested embedded-search workflow with human CAPTCHA intervention, not universal or CAPTCHA-free site compatibility. Deterministic callback-order tests are not a collected native trace. No annotation, emulation or independent sessions are claimed.
